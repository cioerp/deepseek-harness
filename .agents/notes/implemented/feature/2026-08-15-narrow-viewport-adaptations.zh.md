# Agent Note: 窄屏适配（≤1023px）

Status: implemented

[English](2026-08-15-narrow-viewport-adaptations.md) | 中文

## 问题

Web GUI 按宽屏桌面设计：固定 748px 对话列、56px 折叠侧栏占用横向空间、完整会话标题栏、常驻输入框、188px 设置导航栏。手机上这些为价值很低的内容耗尽了本就紧张的宽高。

## 决策

一组窄屏适配，全部对齐既有的 `1024` 自动折叠断点：

- **对话列**改为 `clamp(748px, 72vw, 1200px)`——用 vw 让共享宽度轴的所有消费方解析到同一个值，任何宽度下"输入卡 = 内容 + 32px"的关系都精确成立。
- **折叠侧栏**脱离 CSS Grid 流（轨道 0，对话区全宽），停靠为全宽底部横条：展开/新建/输入/设置。中间列预留其 56px 条带，输入框位于横条之上、无遮挡。工作区区域在收起时让位（展开侧栏可浏览）。
- **会话标题栏**可折叠为一行：移动端默认折叠，桌面默认展开并新增折叠按钮；视口变化保留用户选择。
- **输入框**窄屏默认收起，底部栏「输入」胶囊通过文档化的 `dsh.composer.toggle` 窗口事件切换。离开底部滚动时自动收起（并失焦、收起手机键盘）；滚动测量扣除输入框自身高度并用 40/120px 滞回，折叠不会级联成闪烁。
- **设置面板**改为顶部导航 + 内容堆叠；对话侧边距与用户气泡宽度收紧。

## 验证

各包套件：ui-conversation（标题栏折叠、带滚动几何与 matchMedia 桩的输入框自动隐藏）、ui-layout（网格轨道与横条停靠）、ui-sidebar（底部栏开关派发）、ui-settings-general（移动面板布局）。全部通过；`dsh.composer.toggle` 契约在窗口事件两侧均有断言。

## 考虑过的替代方案

**横条留在流内但用覆盖。** 被拒绝：垂直覆盖会遮住对话内容；为其预留宽度又浪费纵向空间。

**工作区横条横向重排。** 被拒绝：需要重构 ui-workspace 的 rail；收起时隐藏（展开侧栏浏览）是更小、更安全的取舍。

**输入框折叠用原始 scrollHeight 阈值。** 被拒绝：输入框自身高度反馈进测量，在边界处产生闪烁回路。

## 后果

手机获得全宽对话与阅读空间；桌面行为除可选标题栏折叠外不变。`dsh.composer.toggle` 窗口事件是与 `data-conversation-scroll` 类似的跨包字符串契约。收起态的工作区区域需展开侧栏后访问。
